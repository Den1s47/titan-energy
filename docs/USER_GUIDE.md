# Руководство пользователя
## ПАК «Титан-Энергия» (EMS) — MVP

Руководство описывает работу с системой через браузер: что где смотреть,
как выполнять операции диспетчера и как демонстрировать сценарии аварий.

---

## 1. Запуск и вход

**Запуск** (окно терминала должно оставаться открытым, пока работаешь):
```
cd C:\Users\HP\HermesProjects\titan-energy\backend
uv run uvicorn titan.api.app:app --host 127.0.0.1 --port 8000
```
Дождись строки `Application startup complete`.

**Вход:** открой в браузере `http://127.0.0.1:8000`.
На синем экране входа введи логин и пароль:
- администратор: **admin / admin** (по умолчанию)
- диспетчер / наблюдатель: учётки создаёт администратор (см. раздел 6)

После входа слева — панель навигации. Пункты зависят от роли:
| Пункт | Кто видит |
|---|---|
| Мнемосхема, Телеметрия, Журналы, Аналитика | все роли |
| Администрирование, Пульт симулятора | только admin |

Внизу панели — твоя учётка и кнопка «Выйти».

**Роли** (права проверяются на сервере для каждого действия):
| Роль | Что может |
|---|---|
| viewer | только смотреть (схема, графики, журналы без кнопок) |
| dispatcher | + квитирование алармов, телеуправление, экспорт |
| admin | + пользователи, пульт симулятора, журнал действий |

## 2. Мнемосхема (главный экран АРМ)

Раздел «Мнемосхема» — однолинейная схема ТП на светло-сером фоне (как требует ТЗ):

```
Ввод 10 кВ  →  трансформатор Т-1  →  выключатель «Ввод QF1»  →  секция 0,4 кВ
                                                                    ├── Ф-1
                                                                    ├── Ф-2
                                                                    ├── Ф-3
                                                                    └── Ф-4
```

### Как читать индикацию
**Кабельные линии** (линии на схеме):
| Вид | Значение |
|---|---|
| сплошная тёмно-серая | под напряжением, норма |
| пунктирная блёкло-серая | обесточена |
| оранжевая | неопределённое состояние (потеря связи, недостоверные данные) |
| мигающий ярко-красный | аварийный режим (КЗ и т.п.) |

**Коммутационные аппараты** (квадраты):
| Вид | Значение |
|---|---|
| заполненный зелёный квадрат | выключатель включён |
| пустой квадрат | выключатель отключён |
| квадрат с буквой «Р» | местное управление |
| оранжевый квадрат | неопределённое состояние |
| мигающий красный квадрат | аварийное состояние |

**Символ ⚠️** рядом со значениями = параметр вышел за технологические границы
(оранжевый на плитках телеметрии) либо данные недостоверны.

Данные на схеме обновляются раз в секунду автоматически.

## 3. Телеметрия (значения в цифрах)

Раздел «Телеметрия» — плитки с текущими значениями:
- U — напряжение, В
- I — ток, А
- P — активная мощность, кВт
- Q — реактивная мощность, кВАр
- THDu / THDi — нелинейные искажения напряжения/тока, %
- PF — коэффициент мощности
- Выключатель — состояние словами (включён / отключён / местное упр.)
- Код аварии — нет / КЗ (МТЗ) / перегрузка / перенапряжение

Цвет плитки = достоверность: **зелёный** — норма; **оранжевый + ⚠️** — выход
за техно-границы; **красный** — недостоверное значение. Обновление 1 раз/с.

## 4. Аларм-бар и квитирование

Внизу **всех** экранов — лента сообщений об авариях и ненормальных режимах.

**Как читать строку:**
- приоритет цветом: `critical` — красный жирный, `high` — оранжевый,
  `info` — серый;
- время события с точностью до миллисекунд (это важно для оценки
  последовательности срабатываний защит);
- объект и описание («Аварийное отключение по сигналу МТЗ (КЗ)»);
- значение сработки и уставка («знач.: 147.0 / уставка: 400»).

**Порядок строк** (по ТЗ, ISA-18.2): сверху — неквитированные по важности
(critical → high → info), под ними — уже подтверждённые (приглушённые).

**Квитирование:** нажми **«Подтвердить»** в строке события — ты подтверждаешь,
что ознакомился с аварией. Мигание прекращается, в строке появляется
«ack: имя_пользователя». Кнопка видна только роли dispatcher и admin.

## 5. Журналы

Раздел «Журналы» — те же события в виде таблицы с фильтром. В выпадающем
списке «Раздел» четыре журнала (как в ТЗ):
1. **Все события**
2. **Аварийные события** — сработки защит (класс alarm)
3. **Ненормальные режимы** — выходы параметров за границы (abnormal)
4. **Изменения состояний** — возвраты в норму, действия (state)

В строке события: время (мс), приоритет, объект, сообщение со значением/уставкой,
кнопка «Подтвердить» (для dispatcher+). Квитированные показывают кто и когда.

## 6. Телеуправление (отключение/включение ввода)

Доступно ролям **dispatcher** и **admin**. Двухшаговый алгоритм ТЗ:

1. На «Мнемосхеме» нажми **правой кнопкой мыши** на выключатель ввода
   (зелёный квадрат у подписи «Ввод QF1»). Откроется окно «Телеуправление: Ввод».
2. Выбери команду: **«Включить»** или **«Отключить»**.
   - Если ТУ запрещено (например, активная авария) — увидишь красное сообщение
     «Телеуправление запрещено: …» с причиной. Кнопки подтверждения не будет.
3. Появится подтверждение с **обратным отсчётом 10 секунд**. Успей нажать
   **«Выполнить»** — иначе выбор сбросится автоматически (так требует ТЗ).
4. Окно покажет «Выполняется команда…» — система ждёт изменения состояния
   на схеме (до 5 секунд; у «привода» есть задержка ~2 с).
5. Результат:
   - «Команда исполнена: выключатель отключён» — на схеме кабели станут
     пунктирными, квадрат — пустой;
   - «Команда не исполнена: состояние не изменилось» — состояние станет
     «неопределённым», операция сброшена (так бывает при сценарии
     «отказ привода»).
6. **Все шаги**, включая неудачные, записаны в журнал действий оператора
   (см. раздел 7) с твоей учёткой.

## 7. Администрирование (только admin)

Раздел «Администрирование»:

**Пользователи** — таблица учёток. Можно:
- сменить роль (выпадающий список в строке);
- деактивировать/активировать учётку (кнопка «Деактивировать» — вход
  для этой учётки блокируется, учётка не удаляется);
- создать нового: логин + пароль + роль → «Создать».

⚠️ Система не даст админу деактивировать самого себя (защита от потери доступа).

**Журнал действий операторов** — под таблицей. Здесь ВСЕ действия: входы
в систему (в т.ч. НЕУДАЧНЫЕ попытки), квитирования, команды ТУ, инъекции
сценариев, изменения учёток. Каждая строка: время, кто, что, результат,
детали. Требование ТЗ 3.3.2 — аудит с идентификацией диспетчера.

## 8. Пульт симулятора (только admin, учебная фича)

Раздел «Пульт симулятора» — кнопки запуска аварий в «оборудование».
Существует только в MVP: на реальном объекте его не будет.

| Кнопка | Что происходит | Что показать зрителю |
|---|---|---|
| КЗ (сработка МТЗ) | ток ×6, защита отключает ввод | мигающий красный на схеме, critical-аларм, осциллограмма |
| Перегрузка | мощность и гармоники за границы | оранжевые ⚠️ на плитках P и THDi, high-алармы |
| Перенапряжение | U = 460 В | оранжевая плитка U, abnormal-событие |
| Отказ привода ТУ | команда ТУ не исполняется | «неопределённое состояние», неуспех ТУ |
| Потеря связи | Modbus-сервер «умирает» (закрывает соединения) | все точки suspect с ⚠️, оранжевая схема |

Сценарий длится 8 секунд, затем оборудование само возвращается в норму.
(Через API можно задать другую длительность: `&duration_s=30`.)

## 9. Аналитика (MES-уровень)

Раздел «Аналитика» — обработка накопленных в БД измерений.

**Панель «Выбор»** (сверху, как в ТЗ):
- Показатель: P / I / U / THDi
- Период: 5 / 15 / 30 минут
- Усреднение: 30 с / 1 / 3 / 5 мин
- CUSUM target: целевое значение для карты кумулятивных сумм

**Плитки статистики** — Макс / Мин / Среднее / σ по выбранному ряду
(требование ТЗ: «для каждой переменной — Макс/Мин и среднее»).

**Четыре графика:**
1. **Временной ряд** — синяя линия (сырые значения) + зелёная (скользящее
   среднее). Зум: выдели область мышью или колесом; двойной клик — сброс.
2. **Карта Шухарта** — точки процесса с линиями CL (зелёная — среднее),
   UCL/LCL (красные пунктиры ±3σ). **Красная точка** = процесс вышел
   из-под контроля. Все точки между пунктирами = процесс стабилен.
3. **Гистограмма** — распределение значений; оранжевая линия — мода.
   Под графиком подпись: мода, медиана, σ, 3σ.
4. **CUSUM** — накопленное отклонение от target. Если кривая стабильно
   растёт — параметр систематически выше целевого (дрейф); у нуля — в норме.

**Экспорт** (карточка внизу) — кнопки «Скачать CSV» и «Скачать Excel»:
выгружается история выбранного показателя за выбранный период.
Excel-файл открывается в Microsoft Excel / LibreOffice.

## 10. Типовой сценарий демонстрации (5–7 минут)

1. **Мнемосхема** — «вот схема ТП, данные обновляются раз в секунду,
   зелёные квадраты = включено».
2. **Пульт симулятора → Перегрузка** — вернуться на мнемосхему/телеметрию:
   «видите оранжевые ⚠️ — мощность и THDi вышли за границы, система это
   отловила валидацией».
3. **Аларм-бар внизу** — «события с точностью до миллисекунд, приоритеты
   по ISA-18.2» → нажать «Подтвердить» — «мигание прекратилось».
4. **Пульт → КЗ** — «сработка защиты: ввод отключился, схема мигает красным,
   в журнале критический аларм с уставкой».
5. **Телеуправление** — ПКМ по вводу → «Отключить» → отсчёт 10 с → «Выполнить»
   → «состояние изменилось, кабели пунктирные» → обратно «Включить».
6. **Аналитика** — «вот обработка накопленных данных: ряд со скользящим
   средним, Шухарт, гистограмма, CUSUM» → «Скачать Excel» — «отчёт выгружается».
7. **Журнал действий операторов** (admin) — «все действия с учётками,
   включая неудачные попытки».

## 11. Частые вопросы

**Данные не обновляются / плитки оранжевые везде** — у симулятора сценарий
«потеря связи» или сервер перезапускается. Подожди 10 с или проверь окно терминала.

**«Телеуправление запрещено»** — в системе активная авария (код FAULT ≠ 0).
Дождись окончания сценария (8 с) или квитируй аларм.

**Не пускает под admin/admin** — пароль сменили через «Администрирование»
или БД пересоздана. Дефолтный админ создаётся автоматически только при
отсутствии учёток в БД.

**Где хранятся данные** — `backend/titan.db` (SQLite). Копии — `backend/backups/`.

**Как перезапустить систему** — закрыть окно терминала (Ctrl+C) и запустить
команду из раздела 1 заново. Данные в БД сохраняются.

**Сбросить всё к заводским** — удалить `backend/titan.db` и перезапустить:
создадутся пустые таблицы и дефолтный admin/admin.
